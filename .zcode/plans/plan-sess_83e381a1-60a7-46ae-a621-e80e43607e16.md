友链功能重构：归一到 avatar 单字段，友链彻底退出图片系统（不再本地存图）

## 背景
- avatar 字段全链路已存在（模型/DTO/VO/后台表单/前台渲染）但抓图从不碰它
- 现状抓图 = 下载落盘 + image 表记录 + preview_image_id 指针，链路重且是图片 bug 重灾区
- 用户目标：抓图或自定义二选一，图片一律不存后端，避免一条友链两张图的引用管理负担

## 方案
1. **fetchPreview 重写（friendLinkController.js）**：只调 fetchOgMeta，og:image/favicon 的外部 URL 直接写入 avatar；不再 downloadImage/saveImageFile/Image.create；同时置空 preview_image_id（旧本地图由 GC 延迟回收）与弃用的 preview_image；标题/简介空字段自动填充保留；清掉 fs/path/saveImageFile/Image/TMP_DIR 等无用 import
2. **DTO 校验（friendLink.dto.js）**：avatar 只接受 http(s):// 或 // 开头（≤512），拒绝 /uploads/ 与裸 key——防止手填本站路径制造无指针引用（GC 会误删在用图）
3. **存量迁移（migrate-image-ref.js 加幂等步骤）**：avatar 为空且 preview_image 有值 → 归一为完整路径拷入 avatar，保留 preview_image_id（旧指针继续保护旧文件）；preview_image 清空弃用（列保留不删）；重复执行收敛
4. **VO（friendLink.vo.js）**：输出去掉 preview_image 与 previewUrl helper，avatar 原样输出
5. **死代码清理**：ogImage.js 删 downloadImage/decodeImageBuffer（保留 fetchOgMeta）；server/package.json 删 icojs
6. **admin 前端**：表格预览列改读 avatar（加 @error 显示"未设置"）；表单头像 hint 更新；修 `|| undefined` 导致头像/简介清不掉的存量 bug（改 `|| null`）；fetchPreview 响应类型改 { avatar, title, description, message }
7. **home 前端（FriendsView.vue）**：单图渲染——avatar 作 16:10 大封面，去掉叠加小圆头像（同图重复展示）；加 @error 回落站名首字（外链防盗链/死链兜底）；types 同步
8. **不动**：GC 对账 SQL、imageController friend_link 分支（存量指针仍需保护旧文件）、sync-schema（零结构变更）、路由

## 部署顺序
git pull → cd server && npm install（icojs 移除）→ node scripts/migrate-image-ref.js（幂等）→ pm2 restart blog-server → frontend/home 构建构建 → frontend/admin 构建
