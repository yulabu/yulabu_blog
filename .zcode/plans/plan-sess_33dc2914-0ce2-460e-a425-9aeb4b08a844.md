## 问题定性

文章页切主题后"部分样式不跟随、强制刷新才恢复"，是**岛间主题状态不同步**，不是 CSS 或构建问题。

- `views/PostDetailView.vue:161` 的 `watch(() => uiStore.theme, syncMdTheme)` 监听的是**本岛自己那份 pinia**；写主题的只有 `Navbar` 的 `uiStore.toggleTheme`（`stores/ui.ts:37`），它只改自己的 store + `localStorage` + `html[data-theme]`。各岛是独立 Vue app 实例，pinia 各注一份 → PostDetail 的 store 值永不变 → watch 不触发 → `mdTheme` 不翻 → md-editor 的 `.md-editor-dark` 类不生效 → 正文（标题/链接/表格/引用/行内代码/代码块底色）不跟随。站点其它部分是纯 CSS 变量（`main.css:61` 的 `[data-theme="dark"]`），所以正常跟随。
- 硬刷新"恢复"：`onMounted` 调 `syncMdTheme()`（`PostDetailView.vue:216`）重新读 localStorage。
- 佐证：Giscus 没这个毛病，因为它专门用 `MutationObserver` 观察 `html[data-theme]`（`GiscusComments.vue:157-163`），注释里已写明"各岛 pinia 不共享"。

**顺带查实的第二个问题**：`utils/mdEditorSetup.ts` 传了 `instance: hljs`，而 md-editor 的 highlight CSS 注入/切换被守卫短路——源码 `md-editor-v3/lib/es/chunks/index4.mjs:497-523` 的 `noHighlight || a.value || (注入 link)`，产物 `dist/client/_astro/PostDetailView.sDthdsNq.js` 里是同一段（`noHighlight||n.value||(je(\`link\`…`）。结果两个 `?url` 产出的 CSS（`github.DdKuH37F.css` / `atom-one-dark.B-oHczHB.css`）**从未被注入**，任何随包 CSS 里也没有 `hljs-*` 规则（已 grep `@vavt/markdown-theme/css/all.css` = 0 处）→ 代码块目前完全没有语法高亮配色，`mdCodeTheme` 是空转。

## 改动方案

### 第一步：主题改为跨岛共享（根因）
`frontend/home/src/stores/ui.ts`
- 把 `theme` ref 从 store setup 内部（第 20 行）提到**模块作用域**，并补注释说明理由：各岛 pinia 实例独立，模块级 ref 才是同一份 ESM 单例——沿用 `stores/tagFilter.ts` 的既有惯例。
- `setTheme` / `toggleTheme`（写 localStorage + `html[data-theme]`）与 store 的返回值不变；`Navbar`、`PostDetailView` 调用处零改动。
- 不动 `homeHeroCollapsed`（它走 DOM 事件同步，语义不同）。
- SSR 无风险：服务端只把该 ref 初始化为 `'light'` 且从不调用 `setTheme`；两个岛的 SSR 首帧都不读它（Navbar 的 `themeIcon` 有 `isMounted` 门，PostDetail 用自己的 `ref('light')`）。

### 第二步：让代码块配色真正跟随主题
`frontend/home/src/utils/mdEditorSetup.ts`
- 新增导出 `applyHljsCss(theme: 'light' | 'dark')`：按主题在 `githubCss` / `atomOneDarkCss` 之间选 href，确保 `<link id="md-editor-hlCss" rel="stylesheet">` 存在且 href 正确（没有就建、有就改）；`typeof document === 'undefined'` 直接 return。用同一个 id 是为了库里若再注入时会替换而非重复。
- `config({...})` 的 `instance: hljs` **必须保留**：去掉会让 md-editor 去注入 unpkg 的 highlight.js script，违反 AGENTS.md"零第三方外链"约定。
- 注释写明为何要自己管这个 link（库给了 instance 即整体跳过注入与主题切换）。

`frontend/home/src/views/PostDetailView.vue`
- 第 95 行 `import '@/utils/mdEditorSetup'` 改为具名导入 `applyHljsCss`（副作用仍在，且仍先于 md-editor-v3 求值）。
- `syncMdTheme()` 末尾加 `applyHljsCss(mdTheme.value)`。
- 软导航后重新注入无需额外处理：`onMounted` 已调 `syncMdTheme`，而 Astro 的 head swap 会删掉运行时注入的 link，下一个文章页挂载时会重建。

## 验证
1. `cd frontend/home && npm run check && npm run build`（0 error + 构建通过）。
2. 本地 `npm run dev:home` 手测：打开含代码块的文章 → 点主题按钮 → 正文标题/链接/表格/引用/行内代码/代码块底色**当场**跟随，无需刷新；代码 token 在 github / atomOneDark 之间切换；再点回可回退。
3. 反向验证：文章页切主题 → 软导航到首页 → 再进文章页，主题一致；控制台无 hydration mismatch 告警。
4. 暗色用户首次加载仍有 light→dark 的一次切换（既有设计，本次不动）。

## 部署
纯前端改动，无 Nginx / 数据库 / 接口契约变化：
`git pull` → `cd frontend/home && npm install && npm run build`；因 `stores/ui.ts`、`mdEditorSetup.ts` 会进 SSR server chunk，随后 `pm2 restart blog-web`。后台 admin 不受影响（独立 app 与打包）。
