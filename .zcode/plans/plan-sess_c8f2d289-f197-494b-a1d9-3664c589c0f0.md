# 上生产前检查结论 + 部署指令

## 一、检查结论：无阻塞问题

**已实测过高风险项**（此前均真实跑通）：
- dump 可恢复性：导出包曾在临时库完整导入（12 表全部还原）
- 跨进程并发：.lock 文件锁实测（新鲜锁拒绝 409 / 31 分钟过期锁自动接管 / 双进程赛跑一成一败）
- 安全：4 个接口全在 auth 之后；文件名白名单防路径穿越（400）；未登录 401；tar 只打包指定条目（.lock 不会进包）；backups/ 不在 Nginx 静态范围（root 指向 dist，外网摸不到）
- 生产/本地差异：dump 命令自动探测（生产 mariadb-dump 优先）；MySQL 系才追加 --set-gtid-purged=OFF；数据库密码走 chmod 600 临时文件，不上进程命令行
- 前端：备份/导出请求已关超时（绕过 http.ts 全局 15s）；blob 错误体可解析出后端中文报错

**部署注意事项（非阻塞，已纳入下方指令）**：
1. 缺 mariadb-dump 则 `apt install -y mariadb-client`（Debian 12 装 mariadb-server 一般自带）；缺 rsync 则 `apt install -y rsync`
2. cron 里 node 路径先 `command -v node` 确认（NodeSource 应为 /usr/bin/node）
3. admin 站点 /api/ 需加 `proxy_read_timeout 300s`，否则大包导出可能被 Nginx 504
4. 本次零依赖变更：server 不用 npm install；home 未动不用构建；仅 admin 需构建
5. 无 package-lock 变更，git pull 无冲突风险；服务器上未跟踪的 backups/ 不影响 pull
6. 必须 pm2 restart（新路由才加载）
7. 小提示（无害）：cron 日志每行前会有 dotenv@17 的提示横幅；restore.sh 用 mysql 命令，Debian 12 自带兼容符号链接，异常新的系统按包内 README 用 mariadb 替换即可

## 二、部署指令

### 本地（提交推送）
```bash
cd /Users/yulabu/Code/yulabu_blog
git add server/ frontend/admin/ deploy/ .gitignore AGENTS.md
git commit -m "新增备份系统：每日自动备份 + 后台备份管理（导出可用恢复包）"
git push
```

### 服务器（ssh root@206.237.13.114 后执行）
```bash
# 1) 拉代码
cd /var/www/yulabu_blog && git pull

# 2) 工具自检
command -v mariadb-dump || apt install -y mariadb-client
command -v rsync || apt install -y rsync
command -v node   # 确认路径，下方 cron 使用

# 3) 首跑备份验证
cd /var/www/yulabu_blog/server && node scripts/backup.js
ls -lh /var/www/yulabu_blog/backups/db/

# 4) 每日 04:00 自动备份 cron
echo '0 4 * * * root cd /var/www/yulabu_blog/server && /usr/bin/node scripts/backup.js >> /var/log/blog-backup.log 2>&1' > /etc/cron.d/blog-backup
chmod 644 /etc/cron.d/blog-backup

# 5) admin 站点导出超时（编辑 /etc/nginx/sites-available/yulabu-admin 的 location /api/ 块加一行）
#    proxy_read_timeout 300s;
nginx -t && systemctl reload nginx

# 6) 构建后台 + 重启后端
cd /var/www/yulabu_blog/frontend/admin && npm install && npm run build
pm2 restart blog-server

# 7) 验证
pm2 logs blog-server --err --lines 20
# 浏览器登录 admin.yulabu.cn → 备份管理：确认列表、立即备份、导出下载均正常
# 建议把导出包解包检查（含 db/ uploads/ restore.sh README）后存本地一份
```
