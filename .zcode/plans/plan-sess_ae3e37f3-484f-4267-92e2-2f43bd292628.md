# 控制台告警收尾：LXGW 文楷字体自托管（站点做到零第三方外链）

## 取证结论

线上首页的外链资源清单（实测导航到 blog.yulabu.cn 抓取）：**唯一第三方域名 = cdn.jsdelivr.net**——字体样式 + 按 unicode-range 拆分的 woff2 字体子集（中文页约 20-30 个请求，与你控制台 ~28 条告警吻合）。cdn.jsdelivr.net 在 Edge 的跟踪名单内，每个请求触发一条告警。图标（api.iconify）与 md-editor（unpkg）已在此前离线，实测零请求。

你日志里另一条 `Uncaught (in promise) Error: A listener indicated an asynchronous response…` 是**浏览器扩展**的典型报错（扩展 content script 消息通道断开），部分 Tracking Prevention 行也可能来自扩展注入——与站点无关，但站点侧应做到零外链以彻底排除嫌疑。

## 修复：字体自托管（2 处改动）

1. `npm i lxgw-wenkai-webfont`（dependencies）
2. `src/main.css` 头部加 `@import "lxgw-wenkai-webfont/style.css";`——vite 会把 @font-face 引用的全部 woff2 子集打进构建产物
3. `src/layouts/Layout.astro` 删除 jsdelivr 的 `<link rel="stylesheet">` 行

效果：站点对外的第三方域名请求数 = **0**；字体渲染不变（同一字体同一版本）；国内访问还顺带摆脱了 jsdelivr 时不时不稳的问题。

## 验证

1. 本地 + 线上首页：`performance` 资源清单里 **cdn.jsdelivr.net = 0**，字体正常渲染
2. `npm run check` + `build` 全绿；dist 体积增加约 20MB（字体子集按需加载，不阻塞首帧）
3. 你在 Edge 用 **InPrivate（无扩展）** 打开线上站复测：若告警彻底消失 → 全部来自站点（已根除）；若仍刷屏 → 100% 是扩展行为（把报错扩展禁用即可，站点侧已无可修）
